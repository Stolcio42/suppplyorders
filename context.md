# Контекст проекта "Заявки поставщикам"

## Цель
Локальное веб-приложение для формирования заявок поставщикам. Сотрудник выбирает поставщика → добавляет товары в корзину → формирует текстовые сообщения для каждого поставщика, которые можно скопировать.

## Технологии
- HTML, CSS, JavaScript (без фреймворков)
- Запускается локально через Live Server (VS Code)
- Хранение данных: data.json для каталога товаров; localStorage для корзины и истории заказов
- Развёртывание через GitHub Pages (статический хостинг, бесплатно)

## Текущая структура файлов
- index.html (главный интерфейс с авторизацией)
- history.html (отдельная страница истории заказов)
- style.css (все стили)
- script.js (логика работы, корзина, сообщения, localStorage)
- data.json (каталог поставщиков и товаров)
- project-context.md (этот файл)
- images/ (фотографии товаров, именуются по артикулу)

## Основные компоненты интерфейса
- Левая панель: список поставщиков (Деловая упаковка, Цех Бар, Цех Кухня)
- Центральная панель: при старте – инструкция по использованию; после выбора поставщика – сетка карточек товаров
- Правая панель (корзина): сгруппированные по поставщикам товары, управление количеством (+/−, удаление), итоговая сумма, кнопка "Сформировать сообщения", блок с готовыми сообщениями
- При узком экране (≤900px) корзина сворачивается в плавающую кнопку с бейджем количества, открывается полноэкранной панелью
- При нажатии "Сформировать сообщения" корзина раскрывается на весь экран (fullscreen) с разделением на зону товаров (верх) и зону сообщений (низ), каждая со своей прокруткой
- Кнопка "История заказов" в шапке открывает history.html (в этой же вкладке)

## Особенности корзины
- Ограничение количества одного товара — 20 шт
- Увеличение/уменьшение количества кнопками +/− и кнопка "Удалить" под каждым товаром
- Итоговая сумма выводится над кнопкой формирования
- Сообщения генерируются отдельно для каждого поставщика с артикулом, ценой за шт. и общим количеством
- После формирования сообщений корзина **не очищается** (остаётся для дальнейшей работы)

## Сохранение данных (localStorage)
- Ключ `cart`: текущая корзина (обновляется при каждом изменении, восстанавливается при загрузке)
- Ключ `orderHistory`: массив заказов с датой и уникальным id (добавляется при генерации сообщений)
- Данные живут в браузере сотрудника, не удаляются при перезагрузке страницы
- Страница history.html читает orderHistory и позволяет:
  - Просматривать все сохранённые заказы (новые сверху)
  - Удалять отдельные заказы (с подтверждением)
  - Очищать всю историю (с подтверждением)

## Авторизация
- При открытии index.html появляется экран ввода пароля (overlay)
- Пароль задан в коде (переменная CORRECT_PASSWORD)
- После успешного входа состояние сохраняется в sessionStorage до закрытия вкладки
- Без авторизации интерфейс заявок не отображается

## Изображения товаров
- Файлы лежат в папке images/, называются по артикулу (например, 07193.jpg)
- В data.json у товара может быть поле image с путём к файлу
- Если поле отсутствует или файл не найден, показывается SVG-заглушка (📷)
- Изображения загружаются лениво (loading="lazy")
- Размер миниатюр фиксирован (120px), object-fit: cover

## Развёртывание (GitHub Pages)
- Репозиторий: public
- Обновление через веб-интерфейс (Add file → Upload files), коммит в main
- Сайт публикуется автоматически через 20–120 секунд
- Инструкция для сотрудников: открыть ссылку, ввести пароль, работать

## Соглашения по data.json
- Массив объектов поставщиков: { id: number, name: string, products: [...] }
- Товар: { id: number, name: string, article?: string, unit?: string, price?: number, image?: string }

## Планы / Что можно добавить
- Массовое добавление товаров (через CSV → JSON)
- Возможность редактирования заказа из истории (повторное формирование)
- Более гибкая авторизация (несколько пользователей / паролей)
- Подгрузка изображений из внешних источников (по желанию)
